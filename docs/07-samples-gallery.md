# 07 · 控件示例（Samples）与 Gallery 设计

> 对应新增需求：为**每一个控件**写示例，告诉别人怎么用，并展示不同主题、不同 size 的效果——像 WPF 的 MaterialDesignInXamlToolkit 示例程序那样，让人一眼看到每个控件的全部样子。

## 1. 目标与体验参照

WPF 的 Material Design 示例程序之所以经典，是因为它做到了三件事，本库的 Gallery 也要做到：

1. **看得见**：每个控件都有独立展示区，列出它的所有变体、状态、尺寸，不用读文档就知道长什么样。
2. **学得会**：每个示例旁边就是可复制的真实代码，效果与代码一一对应。
3. **验得了**：示例本身就是视觉回归的载体，主题/尺寸一改，全部示例同步变化。

据此定下 Gallery 的三个硬指标：

- **示例覆盖率 100%**：`widgets/` 与 `extra/` 中的每个控件至少 1 个示例页；高频控件（按钮、输入、选择、表格）覆盖全部变体。
- **四维展示**：每个示例可切换 **主题（亮/暗/品牌色）× 密度（标准/紧凑）× 尺寸（大/中/小）× 状态（默认/禁用/加载/选中/错误）**。
- **代码即示例**：展示的代码片段来自真实源码，不是手写的"示意代码"，保证永不过时。

## 2. 为什么 MyGo 能把这件事做得更好

| 能力 | WPF / Web 做法 | MyGo 做法 |
| --- | --- | --- |
| 主题切换 | 切换全局资源字典 / CSS 变量 | `c.SetTheme(&t)`，下一帧全变 |
| **同屏对比亮/暗** | 需两个窗口或复杂逻辑 | **`ui.Themed(c, t)` 局部主题**——同一屏并排渲染亮色与暗色，弹层/Tooltip 自动跟随 |
| 截图回归 | 额外截图工具 | **无窗口渲染 PNG**，同一套示例直接出基线 |
| 代码展示 | 静态文本 | `ui.CodeEditor` 只读内嵌，可直接复制 |
| 即时刷新 | 手动触发渲染 | view = f(state)，切换器改 state 即可 |

**杀手锏是 `ui.Themed`**：可以在一个示例卡片里左右并排渲染同一控件的亮色版与暗色版（或标准与紧凑），这是传统框架需要额外窗口才能做到的。

## 3. Sample 的统一数据结构（设计草案，非实现代码）

```go
// 一个示例单元：标题 + 说明 + 可复制代码 + 实时预览。
type Sample struct {
    Title       string
    Description string
    Code        string                            // 由 go:embed 从真实源码提取
    View        func(c *ui.Context) ui.Element    // 实时渲染
}

// 一个控件的示例集合，由控件包自己提供，Gallery 通过注册表收集。
type WidgetDemo struct {
    Name       string            // "Button"
    Package    string            // "widgets" | "extra"
    Category   Category          // 通用 / 录入 / 展示 / 导航 / 反馈 / 缺口
    Summary    string            // 一句话说明
    Samples    []Sample          // 基础 → 变体 → 状态 → 组合
    Variants   []string          // 该控件支持的 size / type 维度
}

// 注册：每个控件包提供 Samples() 函数，Gallery 启动时汇总。
func Register(d WidgetDemo) // samples/registry.go
```

每个控件包提供一个 `Samples() sample.WidgetDemo`，Gallery 用 `init()` 或显式注册表收集，新增控件时只改控件包自己的文件，不动 Gallery 主程序。

## 4. 每个控件示例的覆盖矩阵（Sample DoD）

一个控件的示例页必须覆盖下表的行×列，至少做到「基础 + 主要变体 + 禁用态 + 三档尺寸」：

| 维度 | 必须展示的内容 |
| --- | --- |
| **用法** | 基础用法 → 进阶用法（事件/绑定）→ 组合用法（与其他控件搭配） |
| **变体** | 控件自身的 type/variant。如 Button：primary / default / dashed / text / link / danger |
| **状态** | default / hover / pressed / **disabled** / **loading** / selected / error（用固定态展示，或说明文字标注） |
| **尺寸** | large / middle / small（映射到 `t.Space` 倍数与 `ant.Size(...)`） |
| **密度** | 标准 / 紧凑（同一示例在两种密度下的效果） |
| **主题** | 亮 / 暗 / 自定义品牌色（通过顶部切换器 + 并排对比） |

以 Button 为例，示例页应包含：

- 基础按钮（点击计数，演示 `Clicked()`）
- 六种 type 变体并排
- 三种 size 并排
- 禁用态与加载态
- 图标按钮与文字+图标按钮
- 危险操作确认（与 Popconfirm 组合）
- **并排对比卡片**：左亮色 / 右暗色，或左标准 / 右紧凑

## 5. Gallery 应用的界面结构

```
┌────────────────────────────────────────────────────────────────┐
│ TopBar: [主题 亮|暗] [品牌色 ▾] [密度 标准|紧凑] [尺寸 大|中|小]   │
│         [☑ 并排对比] [搜索控件...]                                │
├────────────┬───────────────────────────────────────────────────┤
│ 侧栏        │ 示例区（当前控件，如 Button）                       │
│ 通用        │ ┌───────────────────────────────────────────────┐ │
│  ▸ Button   │ │ 基础用法          [预览] [代码] [并排对比]      │ │
│  ▸ Typography│ │ 说明文字...                                   │ │
│ 录入        │ │ ┌─────────────┐                               │ │
│  ▸ Input    │ │ │ [保存] [取消]│  ← 实时控件                    │ │
│  ▸ Select   │ │ └─────────────┘                               │ │
│ 展示        │ │ // 可复制的真实代码片段                        │ │
│  ▸ Table    │ │ ant.Button(c, "保存", ant.Primary())           │ │
│  ...        │ └───────────────────────────────────────────────┘ │
│ 反馈/缺口    │ ... 其余示例卡片 ...                              │
└────────────┴───────────────────────────────────────────────────┘
```

- **左侧**：按分类组织的控件目录，支持搜索过滤，显示覆盖率（如 `Button 7/7`）。
- **中部**：示例卡片流，每张卡片 = 标题 + 描述 + 实时预览 + 代码视图（Tab 切换或上下布局）。
- **顶部控制条**：主题、品牌色、密度、全局尺寸、并排对比开关、搜索。
- **并排对比模式**：用 `ui.Themed` 把当前示例渲染两遍——左亮/右暗 或 左标准/右紧凑，中间加分隔标签。

控制条的实现要点：这些开关只改 app state，view 函数是 state 的函数，下一帧全部示例自动重绘——**不需要逐个刷新示例**。

## 6. 代码片段如何保证"真实不过时"

三种方案对比：

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| A 手写字符串 | 在 Sample 里写一段代码文本 | 简单，但代码与实际实现会漂移 ❌ |
| **B `go:embed` 真实源码（推荐）** | 示例代码写在 `samples/<widget>/` 的真实 `.go` 文件里，用 `// sample:basic ... // /sample` 标记片段，`go:embed` 读取并按标记提取 | 示例即源码，永不漂移 ✅ |
| C AST 提取 | 用 `go/ast` 提取函数体 | 精确但复杂，维护成本高 |

采用 **方案 B**：

```go
// samples/button/basic.go
//go:embed basic.go
var src string

// sample:basic
func basic(c *ui.Context) {
    if ant.Button(c, "保存", ant.Primary()).Clicked() {
        // ...
    }
}
// /sample
```

`sample.Code` 由工具按标记提取 `basic.go` 中 `// sample:basic` 到 `// /sample` 之间的文本，确保展示的就是能编译的真实代码。

代码展示区用只读 `ui.CodeEditor`（MyGo 自带），带「复制」按钮调用剪贴板 API。

## 7. 目录结构与注册表

```
samples/                      # 示例源码：每个控件一个目录，示例即可编译代码
├── registry.go               # WidgetDemo 注册与分类
├── extract.go                # go:embed + 标记提取工具
├── button/
│   ├── basic.go              // 基础 / 点击 / 绑定
│   ├── variants.go           // 六种 type
│   ├── sizes.go              // 三档 size
│   ├── states.go             // 禁用 / 加载 / 选中
│   └── combine.go            // 组合示例
├── input/  select/  table/ ...
├── extra/                    # 缺口控件的示例
│   ├── pagination/  card/  cascader/ ...
└── golden/                   # 每个示例的 PNG 基线
    └── button-basic-light-standard.png ...
gallery/
├── main.go                   # 应用入口：侧栏 + 示例区 + 控制条
├── sidebar.go                # 控件目录与搜索
├── controls.go               # 主题/密度/尺寸/对比切换器
└── render_test.go            # 无窗口渲染全部示例 → 与 golden 对比
```

命名约定：截图基线 `docs/screenshots/<widget>-<variant>-<theme>-<density>.png`，例如 `button-variants-light-standard.png`。文档中可以引用这些**真实生成的** PNG（不要用占位 URL）。

## 8. 截图生成与文档联动

1. `gallery/render_test.go` 遍历注册表，对每个示例在 **亮/暗 × 标准/紧凑** 4 种组合下无窗口渲染 PNG。
2. 输出到 `docs/screenshots/`，与 `golden/` 基线对比，差异即失败。
3. 文档（如各控件 API 页、README 预览）引用这些真实截图。
4. CI 中跑渲染测试，示例或主题一变，截图 diff 立即暴露。

这样示例同时服务于三个目的：**给人看（Gallery）、给人学（文档截图与代码）、给机器验（回归基线）**。

## 9. 编写规范

1. 每个示例必须有 Title、Description、Code（真实源码）、View（实时预览）。
2. 代码必须可独立复制运行，不依赖示例框架内部状态。
3. 覆盖第 4 节的矩阵（至少基础 + 主要变体 + 禁用 + 三档尺寸）。
4. 严守样式铁律（见 `AGENTS.md` 2.1）：示例本身也只读主题、只用 `t.Space/t.Rem`。
5. 在注册表登记，Gallery 侧栏可见。
6. 生成 4 组合截图并通过 diff。
7. 示例中的交互要有明确反馈（如点击计数变化），让人看出控件是"活的"。
